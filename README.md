## 📌 Overview

**Bloop’s Little World** is an interactive, character-driven web experience centered on Bloop, a playful, marshmallow-pink hippo who dreams of creating a world filled with creativity, imagination, and joy.

The project brings together storytelling, playful visual design, character exploration, and browser-based interactive experiences in one cohesive digital world. Visitors can discover Bloop’s story, explore creative projects, meet supporting characters, and interact with the experiences available throughout the website.

The goal is to create a memorable web experience that combines frontend development with imaginative storytelling and playful user interaction.

## 🎯 Project Objectives

- Build an engaging digital world around an original character.
- Combine storytelling, visual design, and interactive experiences.
- Create an intuitive and responsive user interface.
- Encourage exploration and discovery through playful interactions.
- Demonstrate creative frontend development and user experience design.

## ✨ Features

### 🦛 Character and Storytelling

- **Bloop’s Story:** Discover Bloop’s origins, personality, and mission.
- **Character Dossier:** Explore the character’s background and creative abilities.
- **Friends Crew:** Meet the supporting characters in Bloop’s world.
- **Interactive Storybook:** Explore the fictional world through storytelling.

### 🎨 Creative Experiences

- **Play Lab:** Discover imaginative toy concepts and creative projects.
- **Outfit Studio:** Explore character outfit concepts.
- **Art Gallery:** Browse character artwork and illustrations.
- **Character Stickers:** Explore character-themed visual assets.

### 🧸 Interactive Activities

- **Lullaby Lab:** A browser-based audio experience, where implemented.
- **Dreamlight Explorer:** Explore an atmospheric, nighttime-inspired visual experience.
- **Dream Delivery Map:** Discover locations throughout Bloop’s fictional world.
- **Stack Dream Blocks:** A playful block-stacking activity, where implemented.
- **Day and Moonlight Modes:** Explore different visual themes, where available.
- **Hidden Easter Egg:** Discover a surprise interaction through exploration.

> **Note:** Additional features, including 3D character viewing, a guestbook, and character chat, depend on their implementation and configuration in the deployed application.

## 🎨 Design Philosophy

The project follows a warm, playful visual direction inspired by soft textures, pastel colors, rounded interfaces, and friendly character design.

Key design principles include:

- **Character-first design:** Bloop serves as the central visual identity.
- **Playful aesthetics:** Soft colors and rounded components create a welcoming atmosphere.
- **Interactive storytelling:** Visual elements and activities help communicate the fictional world.
- **Responsive layouts:** The interface is designed to adapt to different screen sizes.
- **Accessibility-conscious design:** Keyboard usability, readable content, and reduced-motion support are important considerations.

## 🚀 Getting Started

Follow these steps to run the project locally.

### Prerequisites

- [Node.js](https://nodejs.org/)
- npm
- Git

### 1. Clone the repository

```bash
git clone https://github.com/YogananthJ/Bloop_Bloop.git
```

### 2. Navigate to the project directory

```bash
cd Bloop_Bloop
```

### 3. Install dependencies

```bash
npm install
```

### 4. Start the development server

```bash
npm run dev
```

Open the local URL displayed in your terminal. For a standard Vite configuration, this is usually:

```text
http://localhost:5173
```

### 5. Build for production

```bash
npm run build
```

If the project includes the standard Vite preview script, preview the production build using:

```bash
npm run preview
```

> **Configuration:** Some features may require environment variables or external services. Check the project's configuration files and documentation before enabling them.

## 🔐 Security and Configuration

If the application integrates external services:

- Store private credentials securely.
- Never commit API secrets, database passwords, or privileged service-role keys.
- Configure database permissions and access policies appropriately.
- Keep private API credentials on the server.
- Provide fallback behavior for optional services that are unavailable.

For Supabase integrations, use an appropriate public client key only with correctly configured access policies. Never expose a secret or service-role key in frontend code.

## 📱 Responsive Design and Accessibility

The application aims to support desktop, tablet, and mobile experiences.

Recommended validation includes:

- Checking layouts at narrow and wide viewport sizes.
- Preventing horizontal overflow and overlapping elements.
- Ensuring interactive controls work with touch and keyboard input.
- Providing visible focus indicators and accessible control labels.
- Respecting reduced-motion preferences.
- Offering clear controls for audio experiences.

Document actual device testing and accessibility results only after they have been verified.
